Here's what the Research Agent found:

From your knowledge base: You implemented token bucket rate limiting in your api-gateway project last October using Redis. That pattern is still solid.

Current best practices (2026):

  • Sliding window counters are now preferred over fixed windows — more fair to users
  • Response headers — always include X-RateLimit-Remaining, X-RateLimit-Reset, and Retry-After
  • Tiered limits by plan/role are standard, not just global limits
  • GraphQL-specific — rate limit by query complexity, not just request count

Your existing Redis + token bucket approach is a strong foundation. The main upgrade would be switching to sliding windows and adding per-endpoint tiers.
